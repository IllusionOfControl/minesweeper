# План исправлений проекта Minesweeper

> Основан на [ANALYSIS.md](ANALYSIS.md). Этапы упорядочены так, чтобы сначала
> устранить риски (баги, отсутствие тестов), а потом проводить рефакторинг безопасно.

## Принципы

- Каждый этап заканчивается **зелёной сборкой** и (после этапа 2) **зелёными тестами**.
- Маленькие коммиты с понятными сообщениями; один логический шаг — один коммит.
- Поведение для пользователя не меняется, пока это не оговорено явно.

## Этап 2. Выделение игровой логики + тесты (2–3 дня)

Цель — отделить чистую логику поля от SFML, чтобы покрыть её тестами (фундамент для дальнейшего
рефакторинга).

- [ ] Создать класс `Board` (без зависимостей от SFML):
  - хранит размеры, число мин, состояние клеток;
  - методы: `placeMines(firstClick)`, `reveal(x, y)` (итеративный flood fill — **B3**),
    `toggleMark(x, y)`, `isWin()`, `minesLeft()`, доступ к состоянию клетки.
  - состояние клетки — `enum class`/структура вместо битовой упаковки в `int` (**Q2**).
- [ ] Перенести логику из `GameState` (`initGridArray`, `revealCell`, `markCell`, `checkOnWin`)
  в `Board`; `GameState` оставляет только ввод и рендеринг (**A1**).
- [ ] Заменить `rand()/srand()` на `<random>` внутри `Board` (**Q4**).
- [ ] Исправить игровые правила при переносе в `Board`:
  - **L3** — реализовать «аккорд» (chord): нажатие на открытую цифру, вокруг которой выставлено
    ровно N флагов, открывает всех оставшихся непомеченных соседей; при неверно стоящем флаге —
    проигрыш. Связать с обработкой средней кнопки (заменить нынешний `selectCellsArea`);
  - **L4** — полный сброс модели в `reset()`/конструкторе `Board`;
  - **L5** — вынести правило отрицательного счётчика мин в именованную константу/политику;
  - **L1** — починить условие визуализации победы (относится к рендерингу `GameState`, но
    проверяется тем же сценарием).
- [ ] **L2 — оставить как есть** (безопасна только первая клетка — осознанное решение); вынести
  гарантию в явный, читаемый код `Board::placeMines(firstClick)` и **задокументировать**. Опционально
  предусмотреть расширение безопасности на соседей при `bomb_count <= width*height - 9` (за флагом/
  настройкой), но по умолчанию поведение не менять.
- [ ] Подключить тест-фреймворк (Catch2 или GoogleTest) через CMake `FetchContent`.
- [ ] Написать тесты:
  - расстановка ровно N мин; **первая клетка** никогда не мина (L2 — безопасна одна клетка);
  - корректность чисел-соседей;
  - flood fill раскрывает связную пустую область и её границу; рекурсии нет (B3);
  - постановка/снятие флага и вопроса, баланс счётчика мин (L5);
  - «аккорд»: при верном числе флагов открываются соседи, при неверном — проигрыш/ничего (L3);
  - условие победы; повторный `reset()` не оставляет состояния прошлой партии (L4).

**Критерий готовности:** тесты проходят; `GameState` использует `Board`; визуально игра
ведёт себя корректно во всех сценариях.
